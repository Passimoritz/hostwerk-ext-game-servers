## 1.9.0

- Fixed: LinuxGSM commands in Docker containers ran as root – LinuxGSM refuses that (“CORE: FAIL: … attempted to run as root”), so update, check files, backup, details, the command list, console commands and mods all ended with “code 1”. Every command now runs as the image's own user (read from the container: Config.User, else USER of the image, fallback linuxgsm), with one automatic retry if LinuxGSM still says “as root”. / Behoben: LinuxGSM-Befehle in Docker-Containern liefen als root – das verweigert LinuxGSM („CORE: FAIL: … attempted to run as root“), deshalb endeten Aktualisieren, Dateien prüfen, Backup, Details, die Befehlsliste, Konsolen-Befehle und Mods mit „Code 1“. Jeder Befehl läuft jetzt als eigener Nutzer des Images (aus dem Container gelesen: Config.User, sonst USER des Images, Rückfall linuxgsm), mit einem automatischen zweiten Versuch, falls LinuxGSM trotzdem „als root“ meldet.
- New state “Installing” / “Updating” / “Starting” instead of “Running” while a running container is still installing or updating the game, recognised for every game from the output itself (SteamCMD progress, LinuxGSM's sections “Installing …”, “Checking for Update …”, “Starting …”, the status lines “[ OK ] / [ FAIL ] Starting”, the script log), the image's health check and the Steam query – with a time limit (20 min without output, 10 min starting, 12 h in total) so nothing stays “installing” forever. Afterwards it switches to “Running” by itself, and version and players are queried. / Neuer Zustand „Wird installiert“ / „Wird aktualisiert“ / „Startet“ statt „Läuft“, solange ein laufender Container das Spiel noch installiert oder aktualisiert – für jedes Spiel an der Ausgabe selbst erkannt (SteamCMD-Fortschritt, LinuxGSMs Abschnitte „Installing …“, „Checking for Update …“, „Starting …“, die Statuszeilen „[ OK ] / [ FAIL ] Starting“, das Skript-Protokoll), am Healthcheck des Images und an der Steam-Abfrage – mit Zeitlimit (20 Min. ohne Ausgabe, 10 Min. Startet, 12 Std. insgesamt), damit nichts ewig „installiert“. Danach wechselt er von selbst auf „Läuft“, Version und Spieler werden abgefragt.
- Progress in words: “Downloading: 5.1 GB of 6.4 GB – 20 MB/s, about 2 min. left” (like Hostwerk's model download) in the header, the state card, the console, the server list, Hostwerk's overview tile and as a task in the task window (cancelling it stops the server; the installation continues on the next start). The SteamCMD way shows the same text in its jobs. / Fortschritt in Worten: „Herunterladen: 5,1 GB von 6,4 GB – 20 MB/s, noch etwa 2 Min.“ (wie Hostwerks Modell-Download) im Kopf, in der Zustand-Karte, in der Konsole, in der Server-Liste, in Hostwerks Übersichtskachel und als Aufgabe im Aufgaben-Fenster (Abbrechen stoppt den Server; die Installation geht beim nächsten Start weiter). Der SteamCMD-Weg zeigt denselben Text in seinen Aufgaben.
- While installing/updating: update, check files, check for updates, backup, update LinuxGSM, mods and the game's own commands, console input and the player tab are locked with the reason (ⓘ “Only after the installation”); stop, force and start stay. Triggered anyway (API, schedule), the answer is clear instead of “SteamCMD reports code 1”. / Während Installation/Update: Aktualisieren, Dateien prüfen, Auf Updates prüfen, Backup, LinuxGSM aktualisieren, Mods und die spieleigenen Befehle, Konsolen-Eingabe und der Spieler-Reiter sind mit Grund gesperrt (ⓘ „Erst nach der Installation“); Stoppen, Erzwingen und Starten bleiben. Trotzdem ausgelöst (API, Zeitplan), kommt eine klare Antwort statt „SteamCMD meldet Code 1“.
- Errors name the cause from the output (root, still installing, another LinuxGSM command running, no disk space, Steam/internet unreachable, Steam login needed, Docker off, container gone, no permission, LinuxGSM's own FAIL line) instead of “reports code 1”. / Fehler nennen die Ursache aus der Ausgabe (root, Installation läuft noch, anderer LinuxGSM-Befehl läuft, kein Speicherplatz, Steam/Internet nicht erreichbar, Steam-Anmeldung nötig, Docker aus, Container weg, keine Berechtigung, LinuxGSMs eigene FAIL-Zeile) statt „meldet Code 1“.
- Console: hundreds of “Update state … progress …” lines become one line that updates (also SteamCMD's self-update and curl bars); “Raw output” shows everything exactly. / Konsole: Hunderte „Update state … progress …“-Zeilen werden zu einer Zeile, die sich aktualisiert (auch SteamCMDs Selbst-Update und curl-Balken); „Rohausgabe“ zeigt alles genau.
- Fixed: new LinuxGSM containers got UPDATE_ON_START=1, but the image only checks for “true” – the game was never updated on start. Existing containers are created anew with the right value on their next start or restart (data stays in the volume). / Behoben: Neue LinuxGSM-Container bekamen UPDATE_ON_START=1, das Image prüft aber auf „true“ – das Spiel wurde beim Start nie aktualisiert. Vorhandene Container werden beim nächsten Start oder Neustart mit dem richtigen Wert neu angelegt (die Daten bleiben im Volume).

## 1.7.0

- New “Create game server” dialog in two clear steps: first pick the game (search on top, filters, big cards with the game's picture, popular games first), then set it up (name, free port, where the files go, right on this PC or in Docker, what happens). Explanations sit in one ⓘ instead of text blocks; no more tiny clustered buttons. / Neuer Dialog „Spiele-Server anlegen“ in zwei klaren Schritten: erst das Spiel wählen (Suche oben, Filter, große Karten mit Spielbild, beliebte Spiele zuerst), dann einrichten (Name, freier Port, Speicherort, direkt oder in Docker, was passiert). Erklärungen in einem ⓘ statt Textblöcken; keine gedrängten Mini-Knöpfe mehr.
- Game pictures load: they are looked up by the game (dedicated server tools have no store art of their own), through Steam's current CDN path with the old one as fallback, the store search by name and the LinuxGSM icon – fetched once, kept in Hostwerk's image cache (also offline), initials instead of empty grey boxes. Hostwerk's own server icons use the same pictures (Hostwerk 3.0 or newer). / Spielbilder laden: Sie werden über das Spiel gesucht (Dedicated-Server-Tools haben keine eigenen Shop-Bilder), über Steams aktuellen CDN-Pfad mit dem alten als Rückfall, die Shop-Suche nach Namen und das LinuxGSM-Symbol – einmal geholt, in Hostwerks Bild-Cache gehalten (auch offline), Anfangsbuchstaben statt leerer grauer Kästen. Hostwerks eigene Server-Symbole nutzen dieselben Bilder (ab Hostwerk 3.0).
- Import tab: finds game servers that already exist on this PC – Steam libraries (libraryfolders.vdf, appmanifest), SteamCMD folders, LinuxGSM instances (Linux), LinuxGSM Docker containers and any folder you choose. Take them over where they are or as a copy; port, players and the start line of their script come along. Searching only reads. / Reiter Import: findet vorhandene Spiele-Server auf diesem PC – Steam-Bibliotheken (libraryfolders.vdf, appmanifest), SteamCMD-Ordner, LinuxGSM-Instanzen (Linux), LinuxGSM-Docker-Container und jeden Ordner deiner Wahl. Übernehmen am bisherigen Ort oder als Kopie; Port, Spielerzahl und die Startzeile ihres Skripts kommen mit. Die Suche liest nur.
- Memory hint per popular game (“wants about 16 GB – this PC has 8 GB”), port suggestion without clashes (other game servers and programs on this PC), own folder for a new Steam server, Steam tools with a Linux build can also run in Docker on Windows. / Arbeitsspeicher-Hinweis je beliebtem Spiel („braucht etwa 16 GB – dieser PC hat 8 GB“), Port-Vorschlag ohne Konflikte (andere Spiele-Server und Programme auf diesem PC), eigener Ordner für einen neuen Steam-Server, Steam-Tools mit Linux-Version laufen unter Windows auf Wunsch auch in Docker.
- Removing a server that was taken over in place never deletes its folder. / Ein am bisherigen Ort übernommener Server wird beim Entfernen nie samt Ordner gelöscht.

## 1.6.0

- Game saves in Hostwerk's backup centre (Hostwerk 2.12 or newer): every backup of every server with size and time, restore and delete right there. Restoring stops a running server, first packs the current state as its own backup (“…-before-restore”) and starts the server again afterwards. / Spielstände in Hostwerks Sicherungs-Zentrale (ab Hostwerk 2.12): jede Sicherung jedes Servers mit Größe und Zeit, Zurückspielen und Löschen direkt dort. Beim Zurückspielen wird ein laufender Server gestoppt, der aktuelle Stand vorher als eigene Sicherung gepackt („…-before-restore“) und der Server danach wieder gestartet.
- The off-site backup takes the game saves along (tick “Data from extensions”): the save folder of every Steam server freshly packed, the newest backup of every LinuxGSM server. Docker servers keep their saves in the volume. / Die externe Sicherung nimmt die Spielstände mit (Haken „Daten aus Erweiterungen“): den Spielstand-Ordner jedes Steam-Servers frisch gepackt, die neueste Sicherung jedes LinuxGSM-Servers. Docker-Server behalten ihre Spielstände im Volume.

## 1.4.0

- Docker servers (LinuxGSM) register with Hostwerk's security updates: when Docker Hub has a newer image (Ubuntu, libraries, LinuxGSM), it is pulled, the container is made again (data stays in the volume) and a running server has to keep running – otherwise the previous image comes back. / Docker-Server (LinuxGSM) melden sich bei Hostwerks Sicherheits-Updates an: Gibt es auf Docker Hub ein neueres Image (Ubuntu, Bibliotheken, LinuxGSM), wird es geladen, der Container neu angelegt (Daten bleiben im Volume) und ein laufender Server muss weiterlaufen – sonst kommt das vorige Image zurück.
- Windows: Steam servers start without their own console window. / Windows: Steam-Server starten ohne eigenes Konsolenfenster.
